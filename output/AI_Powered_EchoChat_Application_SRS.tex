\chapter{Introduction}
\section{Purpose}
This Software Requirements Specification (SRS) defines the functional and non-functional requirements for the \textbf{AI Powered EchoChat Application}. EchoChat is a web-based language-exchange and communication platform that enables users to create profiles, discover language partners, build friendships, communicate through real-time chat and video calls, and obtain multilingual help from an AI assistant.

The document is intended for the project team, project guide, evaluators, developers, testers, and future maintainers. It establishes the expected behaviour, interfaces, data requirements, constraints, and quality expectations of the proposed system.

\section{Scope}
EchoChat provides a unified environment for language learners who need communication practice and quick language support. The system includes secure registration and login, profile onboarding, language preferences, recommendations, friend requests, real-time one-to-one messaging, video calls, theme selection, AI chat, translation, and language detection. A language-level test and self-assessment module is included as a planned feature of the application.

The frontend is developed using React and Vite. The backend uses Node.js and Express.js. MongoDB stores user and friendship information. Stream services provide real-time chat and video communication, while Gemini AI supports language-aware assistance.

\chapter{Overall Description}
\section{Product Perspective}
EchoChat is a standalone web application based on a client-server architecture. Users interact with the React frontend in a modern browser. The frontend sends authenticated requests to the Express backend. The backend validates requests, manages session security, stores application data in MongoDB, creates Stream user tokens, and requests AI responses from Gemini when required.

\section{Product Functions}
The major functions of the proposed application are:
\begin{itemize}[leftmargin=0.45in]
\item User registration, login, logout, and protected session management.
\item Profile onboarding with bio, location, native language, and learning language.
\item Recommendation of eligible users for language exchange.
\item Friend-request creation, viewing, and acceptance.
\item One-to-one real-time chat using Stream Chat.
\item Video calls using Stream Video.
\item Gemini-powered AI chat, text translation, and language detection.
\item Persistent visual theme selection using Zustand and browser local storage.
\item Proposed language-level test and self-assessment workflow.
\end{itemize}

\section{Operating Environment}
\begin{itemize}[leftmargin=0.45in]
\item Client: Current versions of Chrome, Edge, Firefox, or another modern web browser.
\item Frontend: React, Vite, React Router, Axios, TanStack Query, Zustand, Tailwind CSS, and DaisyUI.
\item Backend: Node.js, Express.js, Mongoose, bcryptjs, jsonwebtoken, cookie-parser, CORS, and dotenv.
\item Database: MongoDB.
\item External services: Stream Chat, Stream Video, and Google Gemini API.
\item Development tools: npm, Git, GitHub, Postman, and Visual Studio Code.
\end{itemize}

\section{Constraints and Assumptions}
\begin{itemize}[leftmargin=0.45in]
\item A stable internet connection is required for chat, video calls, Gemini requests, and cloud database access.
\item Valid Stream and Gemini API credentials must be available in protected environment variables.
\item A camera and microphone are required for video calls.
\item The application must never expose JWT secrets, Stream server secrets, database URLs, or Gemini keys in the frontend.
\item The accuracy and availability of AI results depend on the external Gemini service.
\end{itemize}

The interface shall be responsive and usable on common desktop and mobile screen sizes. It shall provide pages for registration, login, onboarding, home recommendations, notifications, chat, video calling, and AI assistance. The application shall show page loaders for authentication checks and clear error messages for failed operations.

\section{Communication Interfaces}
The frontend shall communicate with the backend using HTTPS in production and JSON request and response bodies. During development, Axios shall be configured to send cookies using \texttt{withCredentials: true}. The backend shall configure CORS to allow the approved frontend origin and credentials.

\chapter{Data Requirements}
\section{User Data}
The User collection shall include full name, email, password hash, profile picture, bio, native language, learning language, location, onboarding status, friend references, and timestamps. The email address shall be unique.

\section{Friend Request Data}
The FriendRequest collection shall include sender, recipient, request status, and timestamps. In the current implementation, the status values are \texttt{pending} and \texttt{accepted}.

\section{Data Integrity}
The system shall validate all required fields before database writes. Passwords shall never be stored in plain text. Friend requests shall be checked before creation to avoid duplicates. The user model shall use references to represent friendships and Mongoose population shall be used where profile details are required.

\chapter{Security Requirements}
\begin{enumerate}[label=SR-\arabic*.,leftmargin=0.55in]
\item The system shall use bcrypt hashing before a password is persisted.
\item The system shall issue JWT tokens with an expiry period and store them in HTTP-only cookies.
\item The system shall use \texttt{sameSite=strict} cookie configuration and enable secure cookies in production.
\item The authentication middleware shall reject requests that do not have a valid token or an existing user account.
\item The system shall omit password fields from authenticated user responses.
\item The system shall generate Stream user tokens only from the backend.
\item Gemini, Stream server, MongoDB, and JWT secrets shall be stored as environment variables.
\item Future releases should include rate limiting, input schemas, content reporting, user blocking, and audit logging.
\end{enumerate}

\chapter{Acceptance Criteria}
The SRS will be considered satisfied when the application can register and authenticate users securely, enforce onboarding, show valid recommendations, manage friend-request acceptance, issue protected Stream tokens, connect users to real-time chat and video features, and process authenticated AI requests through the backend. The user interface must show clear loading and error states, and the deployment configuration must keep all secret values outside the frontend source code.

\chapter{Future Enhancements}
Future versions may provide language-based matching scores, group conversation rooms, push notifications, persistent AI history, structured AI output, language-learning plans, automated test coverage, user safety controls, request rate limits, moderation, and analytics dashboards.
